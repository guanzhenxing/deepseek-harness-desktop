# DSH 0.1.2-rc.1 Upgrade Qualification Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Determine whether the immutable `dsh-v0.1.2-rc.1` release can safely replace the accepted `0.1.2-alpha.3` runtime in the packaged Desktop product.

**Architecture:** Treat the upgrade as an isolated release candidate, not a dependency refresh inside M5 or M6. Update the complete DSH package family, re-derive format policy from upstream artifacts, and exercise an M4-to-rc.1 packaged upgrade before changing the accepted baseline.

**Tech Stack:** Node 24.11.1, pnpm 11.7.0, Electron 44.1.0, TypeScript, Vitest, Node test runner, official npm packages from `dsh-v0.1.2-rc.1` @ `a66e4702047846cdaa10c66c9d3df3951f5ea70d`.

**Spec:** [Post-M4 delivery design](../specs/2026-09-07-post-m4-delivery-design.md)

## Global Constraints

- Work on `codex/upgrade-dsh-0.1.2-rc.1` from the current accepted post-M4 main line.
- Preserve the M4 `caa5c51` DMG and artifact index byte-for-byte as the previous candidate.
- Every `@deepseek-ai/dsh*` package must resolve to exactly `0.1.2-rc.1`; no mixed family is allowed.
- Keep Electron, Node, pnpm, Cordis, and React versions unchanged unless a hard peer incompatibility proves the candidate impossible; in that case stop rather than expanding scope.
- Never use a real user home, install into `/Applications`, or overwrite the only copy of an accepted artifact.
